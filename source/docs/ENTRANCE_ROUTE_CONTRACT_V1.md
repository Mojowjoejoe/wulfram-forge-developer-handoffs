# Explicit entrance routing contract - source prototype

The legacy access checker proves a connection to a central battlefield but does not require a service approach to traverse an authored entrance. The new opt-in checkFormationAccessViaCorridor accepts an explicit team and ordered entrance points. It connects the battlefield to the first point, follows all authored points, and connects the last point to each selected-team repair/refuel pad. Returned routes preserve the existing pad-to-battlefield receipt direction.

Every joined route receives an 80-unit sampled clearance check, including connections between the grid search and exact authored points. Insufficient clearance rejects; it does not substitute a shortcut. All buildings remain obstacles, except the destination service pad's existing drive-on treatment. Geometry/work budgets and map bounds apply. Duplicate consecutive points reject using the saved-corridor threshold of 0.001 u. The 96-unit preferred and 56-unit fallback access margins remain unchanged.

Sixteen targeted engine/access/Offset tests pass in outputs/entrance-contract-final-tests.log including the duplicate assertion. No prechange byte-golden proof is claimed for legacy behavior.

## Saved policy and portable reuse - source implementation

`lib/entrance-routing.ts` adds `forge.entrance-routing.v1`: one or two explicit unique-team bindings, each naming a corridor and a forward/reverse direction. Direction is battlefield-to-base; a corridor's obstacle team scope does not imply ownership. The immutable candidate helper resolves references, checks reservation bounds/minimum 80-unit width, recomputes current candidate pad routes and removes stale formation.access receipts. Unbound legacy layouts retain no implicit policy. This is an inspection/placement contract, not yet an invariant enforced on every subsequent editor mutation.

Offset favorites now retain the policy in reservation schema 3 and portable library version 4. Existing favorite versions continue to work. New policies reject older schema envelopes; older desktop versions cannot import library version 4. Relocation rotates corridor geometry and recomputes access on the target terrain before assigning metadata. Other corridor families with explicit policies reject favorite capture and require whole-map preservation until supported.

Independent critic found a missing-area early return that could silently discard a dangling policy. Reading and resolving bindings now precedes that return; tests cover absent and empty areas. Follow-up found no further actionable defect.
