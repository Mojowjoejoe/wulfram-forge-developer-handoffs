# Authored-base package: reservations and entrances

`lib/authored-base-package.ts` composes the ordered geometry and authoring graph into the internal `wulfram-authored-base` version-1 file contract. Capture/export/parse/restore preserve all four current build-area kinds and entrance bindings. Areas use the source-to-destination frame delta, matching building geometry. Corridor point order, width, obstacle team and entrance direction remain intact.

Axis-aligned rectangles permit exact 90-degree delta rotations. Other angles reject explicitly; the codec never substitutes a larger enclosing rectangle or loses the rule. Corridors permit arbitrary yaw. Transformed reservations undergo the shared area parser and destination extent/obstacle checks. Without an asset manifest, model-footprint checks remain approximate. Terrain-protection areas establish rules over destination terrain; they do not copy source terrain heights.

Source metadata is retained as provenance, while destination metadata is rebuilt from supported rules. Cached formation access receipts are not reused. Unknown nonempty `forge.*` rules reject with the whole-map export alternative. This prevents a future authoring extension from quietly becoming a decorative provenance field. Opaque `*` records remain outside the geometry codec and reject at capture.

Evidence: `outputs/authored-base-package-tests.log` records 15 passing tests across all three new modules. Package tests cover every area kind, 90-degree and arbitrary corridor rotation, unsupported rectangle angles, nonzero source yaw, repeated-type district indices, retained bindings, stale-receipt exclusion, provenance, dangling bindings, unknown rules, overlap, map bounds, file size/version rejection and input immutability. TypeScript and lint passed in the corresponding `outputs/authored-base-package-typecheck.log` and `outputs/authored-base-package-lint.log`. Independent bounded review found no confirmed defect and requested explicit nonzero-source-frame/repeated-type coverage, now included.

Integration remains open: layout validation settings/provenance handling, personal-library entry type and controls, destination terrain/altitude policy, exact asset checks, entrance access inspection, shared editor constraints, Preview/Apply/Undo and native GUI/MCP acceptance. The restore helper returns an uncommitted candidate, not a validated playable placement. MCP impact is unchanged at this stage: no GUI or public operation exposes the new file contract yet; shared operation and tool support are required in the integration sprint. Existing favorites and serializers are unchanged. No new desktop binary, commit, push or publication. V81 remains the scoped private build and v77 the combined baseline.
