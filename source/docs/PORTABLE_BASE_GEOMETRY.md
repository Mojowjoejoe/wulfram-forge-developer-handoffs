# Authored-base geometry preservation

`lib/portable-base-geometry.ts` adds the ordered building geometry layer on top of [portable authoring references](PORTABLE_AUTHORING_CORE.md). It preserves actual Team 1, Team 2 and neutral records instead of deriving an opponent from Team 1. Supported catalog tokens, cargo subtype, integer activity, pitch, roll and altitude are retained. District membership stays attached to the same serialized indices after IDs change.

The internal version-1 geometry contract uses a rigid origin and yaw frame. Capture subtracts the source origin/yaw; restoration adds the destination origin/yaw. No scaling, team mirroring, sorting, deduplication or terrain snapping occurs. This makes it possible to preserve deliberate asymmetric edits and airborne heights. Destination terrain fitting and the semantics of locked-altitude units must be handled explicitly by the future placement operation, with shared validation and preview.

Evidence: `outputs/portable-base-geometry-tests.log` has 11 passing tests across geometry and authoring. Cases cover JSON round trips, a numerically checked 90-degree frame transform, relocated asymmetric opponents, same-type index membership, cargo/neutral records, orientation/altitude/activity, invalid frames, missing units, changed identities, infeasible spacing, unsupported tokens and atomic rejection. TypeScript and lint passed in `outputs/portable-base-geometry-typecheck.log` and `outputs/portable-base-geometry-lint.log`. Independent review found fractional activity could later truncate during map export; safe-integer validation and legacy integer/rejection regressions resolve the finding. Final bounded review found no remaining actionable issue.

This is internal source groundwork, not yet a personal-library format or a user-visible operation. Geometry metadata contains only the graph supported by the prior module. Complete integration must also preserve reserved areas, entrance bindings and supported provenance; opaque metadata cannot silently disappear. Current axis-aligned rectangular build areas need explicit treatment before arbitrary rotation, while corridor points can rotate directly. Terrain-protection baseline transfer must be defined rather than inferred from a geometry transform.

MCP impact: no existing serializer, transport, tool schema or GUI capability changed. These helpers are intended for shared GUI/MCP placement; final integration still requires a versioned library type, destination validation, preview, one-step Apply/Undo and native GUI/MCP acceptance. The existing favorite guard remains active. No binary was rebuilt for this unconnected codec; v81 remains the latest scoped private build and v77 the combined baseline. Nothing committed, pushed or published.
