# Shared authored-base placement candidate

`lib/authored-base-placement.ts` now restores an authored package into a new layout on a cloned project. Existing layouts and terrain remain intact. The active layout must still match the request, and the new layout ID must be unused. Saved validation settings are now required by the still-internal package contract and validated before placement.

Two explicit terrain modes are implemented: preserve keeps the saved ground-building pose; conform uses the existing sampled terrain snap to recompute altitude/pitch/roll. Starships retain their source absolute altitude and rotation in both modes, matching editor-locked transform semantics. Both modes preserve relative XY and team identities. This is not a replacement or merge into an existing locked layout.

Destination checks require available models, complete map footprints, oriented model radii for spacing and reservation checks, saved layout validation, entrance inspection and shared editor constraints. Preserve checks actual transformed model bounding-box corners against the maximum terrain height across overlapping grid vertices. This conservative envelope can reject physically feasible sloped placements; conform is an explicit alternative. Conform retains the existing sampled support limitations. Neither is game collision proof.

The operation returns a candidate project, affected IDs and entrance inspections without mutating the source. A GUI/MCP integration must still own revision checks, preview presentation and one-step history commit. Cached source analysis is retained only as provenance. This operation is not yet registered as a GUI or MCP capability; that integration and native build acceptance remain required before users can use it.

Evidence: `outputs/authored-base-placement-tests.log` records 37 passing tests including generated 36-building Anvil preservation, old-layout/terrain/input invariance, higher-terrain conformance, preserved-tilt rejection, malformed settings, stale layout/ID/model failures, authored package round trips, oriented reservation strengthening and existing MCP regressions. TypeScript/lint and MCP synchronization passed in corresponding output logs. Independent review identified retained-orientation terrain support; transformed model bounds and a regression fixed it. The second pass found no further actionable issue.

MCP impact: `checkBuildAreas` gains an optional oriented-radius map which can only increase its existing clearance. Existing GUI/MCP callers behave as before; their regressions and synchronization pass. New authored-base operations must be registered through the shared bridge/host/servers in the next integration step. No native build is claimed for the unconnected operation. V81 remains the scoped private build and v77 the combined baseline. No commit, push or publication.
